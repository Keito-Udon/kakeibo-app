# Quickstart: カレンダー表示と月別予算

実装後に、この機能がエンドツーエンドで動くことを確認するための手順。画面ごとの遷移は
[contracts/screens.md](./contracts/screens.md)、APIは [contracts/api.md](./contracts/api.md)、
データと繰越の計算は [data-model.md](./data-model.md) を参照。

## 前提条件

- 001のセットアップ（README.md）が済んでいること
- 本機能のマイグレーションが適用済みであること

```bash
npx prisma migrate dev
npm run dev
```

## 自動テスト

```bash
npm run test       # 繰越計算・日付処理・入力チェックのユニットテスト
npm run test:e2e   # 以下のシナリオのE2Eテスト
```

## 検証シナリオ

日付は2026年9月を今月とした例。実行日に合わせて読み替える。

### 1. 初回の流れ（US2 AC1〜3、US4 AC5）

1. 新しいユーザーAでサインアップしてログインする
2. **期待結果**: グループ作成画面が表示される
3. グループを作成する
4. **期待結果**: 予算決定画面（2026年9月、戻るボタンなし）が表示される
5. `/months/2026-09` を直接開く
6. **期待結果**: 予算決定画面に戻される（FR-003）
7. 設定額20,000円を保存する
8. **期待結果**: カレンダー画面に遷移し、上部に「2026年9月」と残額20,000円が表示される
9. ログアウトして再度ログインする
10. **期待結果**: 予算決定画面を経ずにカレンダー画面が表示される（SC-001）

### 2. カレンダーの日別合計（US1 AC2・AC5）

1. 「＋」から、9月5日の支出1,000円と500円、9月10日の支出2,000円を記録する
2. **期待結果**: 5日のマスに「1,500」、10日のマスに「2,000」、他の日は金額なし。残額16,500円
3. 翌月ボタンで2026年10月に移動する
4. **期待結果**: 10月のカレンダーに切り替わる。残額は36,500円（設定額20,000円の引き継ぎ＋繰越16,500円）

### 3. 日別詳細と編集・削除（US3）

1. 9月5日のマスをタップする
2. **期待結果**: 9月5日の詳細画面に、2件の支出の金額・内容・支払者・支払い方法が表示される
3. 1,000円の支出を編集して、支出日を9月6日に変更する
4. **期待結果**: 9月6日の詳細画面に移り、カレンダーでは5日が「500」、6日が「1,000」になる
5. 500円の支出を削除する
6. **期待結果**: 一覧から消え、カレンダーの5日の金額が消え、残額が500円増える

### 4. 予算変更と繰越（US2 AC4〜9）

1. カレンダー上部の「2026年9月」をタップする
2. **期待結果**: 9月の予算画面に、設定額20,000円・繰越0円が表示される
3. 10月に移動して設定額を25,000円に変更する
4. **期待結果**: 10月の予算 ＝ 25,000円 ＋ 9月の残額。9月の設定額は20,000円のまま
5. 9月に23,000円分の支出があるよう追加する（3,000円超過）
6. **期待結果**: 9月の残額が赤字の −3,000円、10月の予算が 25,000 − 3,000 ＝ 22,000円になる（FR-012）
7. 8月（予算開始月より前）に移動する
8. **期待結果**: 残額が「予算なし」と表示される

### 5. 2人での自動反映（US1 AC6、FR-009, FR-021）

1. ユーザーAが3点リーダー →「招待リンク」でリンクを発行する
2. ユーザーB（別ブラウザ）がサインアップ・ログインし、招待リンクから参加する
3. **期待結果**: ユーザーBは予算決定画面を経ずにカレンダー画面に遷移する（US2 AC3）
4. 両方がカレンダーを開いた状態で、ユーザーAが支出を追加・編集・削除し、予算を変更する
5. **期待結果**: ユーザーBの日別合計と残額が、操作なしで数秒以内に更新される

### 6. 複数グループ（US4）

1. ユーザーAが3点リーダー →「グループ作成」で2つ目のグループを作る
2. **期待結果**: 新しいグループの予算決定画面が表示される。設定額を保存すると、新しいグループの
   カレンダー（支出なし）が表示され、上部に新しいグループ名が出る
3. 3点リーダー →「グループ切り替え」で最初のグループを選ぶ
4. **期待結果**: 最初のグループのカレンダーと支出が表示される
5. ログアウトして再度ログインする
6. **期待結果**: 最初のグループ（最後に選んだグループ）のカレンダーが表示される（FR-028）

### 7. 入力の拒否（FR-007, FR-022）

1. 予算画面で0円、支出追加画面で0円・マイナスの金額を保存しようとする
2. **期待結果**: どちらもエラーメッセージが表示され、保存されない

### 8. 既存データの移行（Edge Cases）

001の状態のDB（予算設定済みグループと支出あり）に対してマイグレーションを適用し、次を確認する。

1. 既存グループでログインすると、予算決定画面を経ずにカレンダー画面が表示される
2. 既存の支出が、記録した日（日本時間）のマスに表示される
3. 移行した月の予算画面に、移行前の月次予算額が設定額として表示され、繰越は0円である
