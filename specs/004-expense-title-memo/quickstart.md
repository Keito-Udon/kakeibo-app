# Quickstart: 支出のタイトルとメモ

実装後に、この機能が動くことを確認する手順。画面は [contracts/screens.md](./contracts/screens.md)、APIは
[contracts/api.md](./contracts/api.md)、データと移行は [data-model.md](./data-model.md) を参照。

## 前提条件

```bash
# 移行の前に DB を退避する（002 と同じ）
mkdir -p ~/kakeibo-backups && cp prisma/dev.db ~/kakeibo-backups/dev-before-004-$(date +%Y%m%d%H%M%S).db
npx prisma migrate deploy
npm run test       # 文字数・入力チェックのユニットテスト
npm run test:e2e   # 以下のシナリオのE2E
```

## 検証シナリオ

### 1. タイトルとメモを入力して記録する（US1 AC1〜2）

1. 支出追加画面でタイトル「スーパー」、メモに2行「野菜・牛乳」「○○店」を入力して保存する
2. **期待結果**: 日別詳細に「スーパー」とその下に2行のメモが表示される。編集画面を開くと同じ内容が入っている
3. タイトルだけで保存する
4. **期待結果**: 保存でき、日別詳細にはタイトルだけが表示される

### 2. 入力の拒否（US1 AC3〜4）

1. タイトルを空、または空白だけで保存しようとする
2. タイトルに51文字、メモに201文字を入力する
3. **期待結果**: 文字数の表示が赤くなり、保存するとエラーが出て保存されない
4. 絵文字を含むタイトル（例: 「🍙」×50）を入力する
5. **期待結果**: 「50/50」と表示され、保存できる（見た目の1文字を1文字として数える）

### 3. 編集でメモを消す（US1 AC5）

1. メモのある支出を編集し、メモを空にして保存する
2. **期待結果**: 日別詳細にメモが表示されなくなる

### 4. 自動反映（US2 AC4）

1. Bが日別詳細を開いたまま、Aがその日の支出のメモを変更する
2. **期待結果**: Bの画面が数秒以内に更新される

### 5. 既存データの移行（FR-007, SC-002）

1. 移行前のDBのコピーに、「内容」が50文字と51文字以上の支出を含めた状態でマイグレーションを適用する
2. **期待結果**: 50文字以下はタイトルがそのまま、51文字以上はタイトルが先頭50文字・メモが全文になる。
   件数・金額の合計は移行前と一致する
