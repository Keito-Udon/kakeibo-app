# Feature Specification: 支出のタイトルとメモ（Expense Title & Memo）

**Feature Branch**: `004-expense-title-memo`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "支出の内容に書き方の制限があるので、タイトルとメモ欄の項目を用意する設計にしたい。（確認済み: タイトルは必須・最大50文字／メモは任意・改行可・最大200文字／日別詳細の一覧ではタイトルの下にメモの全文を折り返して表示する／既存の「内容」はタイトルに移し、51文字以上のものは先頭50文字をタイトル、全文をメモに入れる）"

## 背景と前提

現在、支出には「内容」という欄が1つだけあり、1行・必須・最大200文字で入力する。日別詳細の一覧では1行で
切れて末尾が省略されるため、長く書いた内容は読めない。「何に使ったか」を短く示す部分と、内訳や店名などの
補足を書く部分が1つの欄に混ざっていることが、書きにくさの原因である。本機能では、この欄を **タイトル**
（何に使ったかを短く）と **メモ**（補足を自由に、改行可）に分ける。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タイトルとメモを分けて支出を記録する (Priority: P1)

メンバーは支出を追加・編集するとき、タイトル（必須）とメモ（任意、改行可）を別々に入力できる。
タイトルには「スーパー」のように何に使ったかを短く書き、メモには内訳や店名などを複数行で書ける。

**Why this priority**: 本機能の目的そのもの。入力欄が分かれていなければ、表示の改善（US2）も意味をなさない。

**Independent Test**: 支出追加画面でタイトル「スーパー」、メモ「野菜・牛乳\n○○店」を入力して保存し、
編集画面を開くと、タイトルとメモ（改行を含む）が入力したとおりに表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** メンバーが支出追加画面を開いている、**When** タイトル「スーパー」と、2行のメモ「野菜・牛乳」「○○店」を入力して保存する、**Then** 支出が記録され、編集画面を開くとタイトルとメモが改行を含めて入力したとおりに表示される
2. **Given** メンバーが支出追加画面を開いている、**When** タイトルだけを入力し、メモを空のまま保存する、**Then** 支出が記録される（メモは任意）
3. **Given** メンバーが支出追加画面を開いている、**When** タイトルを空のまま（または空白だけで）保存しようとする、**Then** 保存されず、タイトルが必要である旨が表示される
4. **Given** メンバーが支出追加画面を開いている、**When** タイトルに51文字以上、またはメモに201文字以上を入力して保存しようとする、**Then** 保存されず、上限を超えている旨が表示される
5. **Given** 支出が記録されている、**When** メンバーが支出編集画面でタイトルやメモを変更して保存する、**Then** 変更が保存される（メモを空に戻すこともできる）

---

### User Story 2 - 日別詳細でタイトルとメモを省略せずに読む (Priority: P2)

日別詳細の一覧では、各支出のタイトルと、その下にメモの全文（改行を保ったまま折り返し）が表示される。
長いメモも、編集画面を開かずに一覧で読める。

**Why this priority**: 書いた内容を一覧で読めるようにする改善。US1だけでも記録と編集画面での確認はできる
ため、P2とする。

**Independent Test**: 2行・合計150文字のメモを持つ支出がある日の日別詳細を開き、タイトルと、メモの全文が
改行を保って省略なく表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** タイトル「スーパー」、メモ「野菜・牛乳」「○○店」（2行）の支出がある、**When** その日の日別詳細を開く、**Then** 「スーパー」の下に、メモが2行のまま表示される
2. **Given** メモが150文字の支出がある、**When** その日の日別詳細を開く、**Then** メモの全文が省略されずに、画面の幅で折り返して表示される
3. **Given** メモが空の支出がある、**When** その日の日別詳細を開く、**Then** タイトルだけが表示され、メモのための空の行や見出しは表示されない
4. **Given** メンバーBが日別詳細を開いたままにしている、**When** メンバーAがその日の支出のタイトルやメモを変更する、**Then** Bの画面にも数秒以内に反映される（002の自動反映を維持）

---

### Edge Cases

- タイトル・メモの前後の空白（改行を含む）は保存時に取り除く。取り除いた結果タイトルが空なら拒否し、メモが空なら「メモなし」として扱う
- 文字数は、見た目の1文字を1文字として数える（全角・半角、絵文字を区別しない）。改行は1文字として数える
- メモの途中の改行はそのまま保存・表示する。連続する空行もそのまま保つ
- タイトルに改行は入れられない（1行の入力欄）
- 既存の支出の移行: 今の「内容」が50文字以下なら、そのままタイトルにし、メモは空にする。51文字以上なら、先頭50文字をタイトル、全文をメモに入れる。今の「内容」は最大200文字なので、全文が必ずメモの上限（200文字）に収まり、移行で文字は失われない
- 入力中に上限に近づいたことが分かるよう、タイトルとメモの入力欄には、前後の空白を除いた現在の文字数と上限（例: 「12/50」）を表示する（保存時の判定と同じ数え方）
- 編集中に他のメンバーがその支出を削除した場合の扱いは002のまま（保存時に既に削除された旨を表示）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 支出は「タイトル」と「メモ」を持たなければならない（MUST）。001・002の「内容」はタイトルに置き換える
- **FR-002**: タイトルは必須で、前後の空白を除いて1文字以上50文字以下、かつ改行を含まないものでなければならない（MUST）。追加・編集のどちらでも、条件を満たさない場合は保存を拒否し、理由を表示する
- **FR-003**: メモは任意で、前後の空白を除いて200文字以下でなければならない（MUST）。改行を含められる。空（空白だけを含む）の場合は「メモなし」として保存する
- **FR-004**: 支出追加画面と支出編集画面は、タイトル（1行）とメモ（複数行）の入力欄を持ち、それぞれに現在の文字数と上限を表示しなければならない（MUST）
- **FR-005**: 日別詳細の一覧は、各支出のタイトルと、その下にメモの全文を表示しなければならない（MUST）。メモは改行を保ち、画面の幅で折り返し、省略しない。メモがない支出ではメモの領域を表示しない
- **FR-006**: タイトル・メモの追加・変更は、他のメンバーの日別詳細にも再読み込みなしで数秒以内に反映されなければならない（MUST。002のFR-021を維持）
- **FR-007**: 既存の支出は、Edge Cases の規則で「内容」からタイトル・メモへ移行しなければならない（MUST）。移行の前後で支出の件数と金額は変わらず、「内容」の文字は失われない
- **FR-008**: 001〜003の要件（支出の追加・編集・削除、支払者・支払い方法・支出日、カレンダー、メンバーごとの支払額、グループ外への非公開）は維持しなければならない（MUST）

### Key Entities

- **ExpenseRecord（支出記録）**: 「内容」をタイトル（必須、1〜50文字）に置き換え、メモ（任意、0〜200文字、改行可）を加える。その他の項目は変更しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 200文字以内のメモは、日別詳細で1文字も省略されずに読める
- **SC-002**: 移行後、既存のすべての支出について「移行前の内容」＝「タイトル」（50文字以下の場合）または「メモ」（51文字以上の場合）が成り立ち、件数・金額の合計が移行前と一致する
- **SC-003**: メンバーは、タイトルとメモを入力して支出1件を30秒以内に記録できる（002のSC-006と同じ水準）

## Assumptions

- タイトルは既存の「内容」と同じく、日別詳細の一覧で各支出の見出しとして使う。カレンダーの日付マス・メンバーごとの支払額の表示には、タイトルもメモも出さない（変更なし）
- メモの内容で支出を検索する機能は本機能のスコープ外
- メモに書いたURLを自動でリンクにする、太字にするなどの書式は扱わない（入力したとおりの文字として表示する）
- 支出追加・編集画面の他の項目（金額・支払者・支払い方法・支出日）とその入力チェックは変更しない
