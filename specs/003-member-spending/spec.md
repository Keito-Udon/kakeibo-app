# Feature Specification: メンバー別の使用額の可視化（Member Spending）

> 本仕様でいう「使用額」は、支払者で集計した **支払額**（そのメンバーが支払者である支出の合計）を指す。
> 本文・plan・tasks では「支払額」と書く。

**Feature Branch**: `003-member-spending`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "グループに参加するユーザー別で使用した金額を可視化したい。カレンダーと同じ画面内で、左に可視化したい。（確認済み: カレンダーと同じ画面でよい／スマホでも左側に置く／支払者を基準に数える／表示中の月について、メンバーごとの金額と全体に占める割合を表示する）"

## 背景と前提

`specs/002-calendar-monthly-budget` で作ったカレンダー画面に、表示中の月の「誰がいくら払ったか」を加える。
002では「1画面1機能」（FR-004）の方針でカレンダー画面の役割を「その月の支出を日付ごとに見る」として
いた。本機能では、カレンダー画面の役割を **「表示中の月の支出状況を見る」** と捉え直し、日付ごとの
支出とメンバーごとの支出を、同じ月の状況を見るための1つの役割として同じ画面に置く（ユーザー確認済み）。
支出の入力・予算の変更など、見る以外の操作は引き続き別画面で行う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 表示中の月の、メンバーごとの支払額を一目で見る (Priority: P1)

グループのメンバーは、カレンダー画面の左側で、表示中の月に各メンバーがいくら払ったかと、それが
月の支出全体の何割にあたるかを確認できる。共有財布の支出の偏り（片方ばかりが払っている等）に
気づけるようにする。

**Why this priority**: 本機能の目的そのもの。これだけで「誰がどれだけ払ったか」が分かる価値がある。

**Independent Test**: 2人のグループで、ある月にメンバーAが3,000円、メンバーBが1,000円を支払者として
記録した状態でカレンダー画面を開き、左側にAが3,000円・75%、Bが1,000円・25%と表示されることを
確認できる。

**Acceptance Scenarios**:

1. **Given** 2026年9月にメンバーAが支払者の支出が合計3,000円、メンバーBが支払者の支出が合計1,000円ある、**When** メンバーが2026年9月のカレンダー画面を開く、**Then** カレンダーの左側に、Aの支払額3,000円と割合75%、Bの支払額1,000円と割合25%が、割合の大きさが分かる棒とともに表示される
2. **Given** メンバーAが記録した支出の支払者がメンバーBである、**When** カレンダー画面を開く、**Then** その支出はBの支払額として数えられる（記録した人ではなく支払者で数える）
3. **Given** 2026年9月にメンバーBが支払者の支出が1件もない、**When** 2026年9月のカレンダー画面を開く、**Then** Bも一覧に表示され、支払額0円・割合0%と表示される
4. **Given** 2026年9月の支出が1件もない、**When** 2026年9月のカレンダー画面を開く、**Then** 全員の支払額が0円と表示され、割合の代わりに支出がないことが分かる表示になる
5. **Given** カレンダー画面で2026年9月を表示している、**When** 翌月（2026年10月）に移動する、**Then** 左側の表示も2026年10月の支払額と割合に切り替わる
6. **Given** メンバーBがカレンダー画面を開いたままにしている、**When** メンバーAが支出を追加・編集（支払者の変更を含む）・削除する、**Then** Bの画面の左側の支払額と割合が、再読み込みなしで数秒以内に更新される

---

### User Story 2 - 狭い画面でも、正確な金額とメンバー名をそのまま読む (Priority: P2)

スマホの幅でも、左側の表示はメンバー名と支払額を省略せずに表示する。メンバーは、タップなどの
追加の操作をせずに、各メンバーの名前と正確な支払額（1円単位）を読める（ユーザー確認済み: 左の列を
広めに取り、省略しない）。

**Why this priority**: US1の表示を狭い画面でも役立てるための条件。US1が成立していれば偏りには
気づけるため、P2とする。

**Independent Test**: スマホの幅でカレンダー画面を開き、左側に各メンバーの名前と正確な支払額が
省略されずに表示され、同時にカレンダーの日付マスの日付と金額も読めることを確認できる。

**Acceptance Scenarios**:

1. **Given** メンバーA「けいと」の2026年9月の支払額が12,345円である、**When** スマホの幅でカレンダー画面を開く、**Then** 左側に「けいと」と「12,345円」が省略されずに表示される
2. **Given** スマホの幅でカレンダー画面を開いている、**When** 追加の操作をせずに画面を見る、**Then** 左側のメンバーごとの表示と、カレンダーのすべての日付マスの日付・金額の両方が読める

---

### Edge Cases

- メンバーの表示名が長い場合（表示名は最大50文字）は、省略せずに折り返して表示し、左側の領域から横にはみ出さない
- 支払額の桁数が多い場合（例: 1,234,567円）も、省略せずに表示する（必要なら折り返す）
- メンバーの表示名の先頭の文字が同じ2人（例: 「けいと」と「けんた」）でも、見分けられる表示になる
- 割合は整数（%）で表示する。四捨五入の結果、全員の合計が100%にならない場合があってもよい（各メンバーの割合を正しく丸めることを優先する）
- 予算開始月より前の月（002で「予算なし」と表示される月）でも、支出があればメンバーごとの支払額と割合を表示する（支払額の表示は予算の有無に関係しない）
- 支出日を別の月に変更した支出は、変更後の月の支払額として数えられる
- グループのメンバーが3人以上いる場合も、全員を表示する（グループ人数の上限は設けていない）
- 表示するのは選択中のグループのメンバーと支出だけで、他のグループの支出は含めない（002のFR-029）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: カレンダー画面は、表示中の月について、グループの各メンバーが支払者である支出の合計（支払額）を表示しなければならない（MUST）。支払額は記録した人ではなく支払者で数える
- **FR-002**: 各メンバーの支払額が、その月の支出合計に占める割合を、整数の%と、割合の大きさが分かる棒で表示しなければならない（MUST）
- **FR-003**: 支払額が0円のメンバーも表示しなければならない（MUST）。その月の支出が1件もない場合は、割合の代わりに支出がないことが分かる表示にする
- **FR-004**: メンバーごとの表示は、カレンダー画面の中で、カレンダーの左側に置かなければならない（MUST）。スマホなど横幅の狭い画面でも左側に置く
- **FR-005**: 左側の表示は、メンバー名と支払額を省略せずに表示できる幅を取らなければならない（MUST）。同時に、カレンダーの日付マスの日付と金額が読めなくならないよう、カレンダーの幅を確保しなければならない（MUST）。両立しない場合の優先順位は plan で決める
- **FR-006**: 各メンバーの表示名と正確な支払額（1円単位、例: 「12,345円」）は、タップなどの追加の操作なしに、カレンダー画面の左側で読めなければならない（MUST）
- **FR-007**: 月を移動すると、メンバーごとの表示も移動先の月に切り替わらなければならない（MUST）
- **FR-008**: 支出の追加・編集（支払者・支出日の変更を含む）・削除は、他のメンバーの画面のメンバーごとの表示にも、再読み込みなしで数秒以内に反映されなければならない（MUST）
- **FR-009**: メンバーごとの表示は、表示名の先頭の文字が同じメンバーがいても見分けられなければならない（MUST）。表示名を省略しないこと（FR-006）で満たす
- **FR-010**: 002の要件（カレンダー画面の残額・日別合計・月移動・メニュー、支出の追加・編集・削除、グループ外への非公開）は維持しなければならない（MUST）。カレンダー画面の役割は「表示中の月の支出状況を見る」とし、支出の入力や予算の変更は引き続き別画面で行う

### Key Entities

- **メンバーごとの支払額（導出値）**: 表示中の月・選択中のグループについて、メンバーごとに「支払者がそのメンバーである支出の金額の合計」。保存せず、支出記録から求める
- **割合（導出値）**: メンバーの支払額 ÷ その月の支出合計。その月の支出合計が0円のときは求めない
- **ExpenseRecord / GroupMember / User**: 002から変更なし（支払者・支出日・金額・表示名を使う）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: カレンダー画面を開いてから3秒以内に、表示中の月で誰がいちばん多く払ったかを読み取れる
- **SC-002**: 表示されるメンバーごとの支払額の合計は、その月のカレンダーの日別合計の総和と常に一致する
- **SC-003**: スマホの幅（横幅約390px）でも、メンバーごとの表示を加えたあとで、カレンダーのすべての日付マスの日付と金額が省略されずに読める
- **SC-004**: あるメンバーの支出の変更が、他のメンバーの画面のメンバーごとの表示に、操作なしで数秒以内に反映される

## Assumptions

- 集計期間は、カレンダーで表示している暦月（日本時間、1日〜末日）とする。002と同じく支出日で数える
- 表示の並び順は、支払額の多い順とする（同額なら先にグループに参加した順）
- 各メンバーは同じ色で表示し続ける（月を移動しても色が変わらない）
- 横幅の広い画面（パソコン・タブレット）でも、カレンダーの左側に置く
- 立て替え精算（誰が誰にいくら返すか）の計算は本機能のスコープ外とする（企画メモのPhase 2以降の候補）
- 予算の按分（メンバーごとの予算）は行わない。予算・残額はグループ全体のまま
- 支払い方法（現金／モバイル決済）別の内訳は本機能では表示しない
