# Quickstart: メンバー別の使用額の可視化

実装後に、この機能が動くことを確認する手順。画面の配置は [contracts/screens.md](./contracts/screens.md)、
APIは [contracts/api.md](./contracts/api.md)、計算は [data-model.md](./data-model.md) を参照。

## 前提条件

- 002のセットアップと移行が済んでいること（データ構造の変更はないため、新しいマイグレーションはない）

```bash
npm run dev
npm run test       # 割合の計算・支払者別の集計のユニットテスト
npm run test:e2e   # 以下のシナリオのE2Eテスト
```

## 検証シナリオ

日付は2026年9月を今月とした例。

### 1. 支払者ごとの金額と割合（US1 AC1〜3）

1. ユーザーA・Bが同じグループに所属し、今月の予算が設定済みの状態にする
2. Aが「支払者: A」で3,000円、「支払者: B」で1,000円の支出を記録する（Bの分はAが記録する）
3. **期待結果**: カレンダーの左に、A 3,000円・75%、B 1,000円・25%の順で表示される（記録した人ではなく
   支払者で数える）
4. Bが支払者の1,000円を削除する
5. **期待結果**: B は 0円・0% で表示され続け、A は 3,000円・100% になる

### 2. 支出のない月・月の移動（US1 AC4〜5）

1. 翌月に移動する
2. **期待結果**: 左の列が翌月に切り替わり、全員が0円・「支出なし」になる

### 3. 自動反映（US1 AC6）

1. Bの画面でカレンダーを開いたまま、Aが支出を追加し、別の支出の支払者をBに変更する
2. **期待結果**: Bの画面の左の列が、操作なしで数秒以内に更新される

### 4. 狭い画面（US2、SC-003）

1. 横幅390pxと360pxでカレンダーを開く。表示名が長いメンバー（例: 20文字）と、支払額が6桁以上の
   メンバーがいる状態にする
2. **期待結果**: 左の列に表示名と支払額が省略されずに表示され（名前は折り返す）、カレンダーのどの日付マス
   でも金額がマスからはみ出さない。画面に横スクロールが出ない

### 5. 合計の一致（SC-002）

1. 支出が複数ある月で、左の列の支払額の合計と、カレンダーの日別合計の総和を比べる
2. **期待結果**: 一致する
