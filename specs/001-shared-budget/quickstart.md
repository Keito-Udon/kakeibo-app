# Quickstart: 共有家計簿（Shared Budget）

実装後に、このフィーチャーがエンドツーエンドで動くことを確認するための手順。詳細な実装コードは
`tasks.md`（`/speckit-tasks`で生成）およびソースコードを参照し、ここでは検証シナリオのみを示す。

## 前提条件

- Node.js 22+ がインストール済み
- 依存パッケージがインストール済み（`npm install`）
- `.env` に少なくとも以下が設定されていること
  - `DATABASE_URL="file:./prisma/dev.db"`
  - Auth.js用のシークレット（例: `AUTH_SECRET`）
- Prismaのマイグレーションが適用済み（`npx prisma migrate dev`）

## セットアップ

```bash
cd ~/kakeibo-app
npm install
npx prisma migrate dev --name init
npm run dev
```

ブラウザで `http://localhost:3000` を開く。

## 検証シナリオ

### 1. アカウント作成とグループ作成（User Story 1 の前提）

1. `/signup` でユーザーA（例: `a@example.com`）を作成する
2. ログインし、グループ（例:「テスト家計簿」）を作成する
3. **期待結果**: トップ画面にグループ名が表示され、支出記録が0件の状態で表示される

### 2. 招待リンクでの参加（User Story 1, FR-014）

1. ユーザーAとしてログインした状態で招待リンクを発行する
2. 別ブラウザ（またはシークレットウィンドウ）で `/signup` からユーザーBを作成し、ログインする
3. 発行された招待リンク（`/invite/{token}`）にアクセスする
4. **期待結果**: ユーザーBが同じグループのメンバーになり、トップ画面にグループの支出記録が見える

### 3. 支出の記録と共有閲覧（User Story 1, acceptance scenario 1・4）

1. ユーザーAの画面で支出（金額1,500円、内容「コンビニ」、支払い方法「モバイル決済」）を記録する
2. ユーザーBの画面を数秒間何も操作せず開いたままにする
3. **期待結果**: ユーザーBの画面がリロードなしで数秒以内にその支出記録を表示する（FR-013, SC-002）

### 4. 相互編集・削除（acceptance scenario 5, FR-012）

1. ユーザーBが、ユーザーAが追加した支出記録の金額を編集する
2. **期待結果**: 編集内容がユーザーAの画面にも数秒以内に反映される
3. ユーザーAがその記録を削除する
4. **期待結果**: 両方の画面から記録が消える

### 5. 月次予算と残額表示（User Story 2）

1. グループの月次予算を20,000円に設定する
2. 合計12,000円分の支出を記録する
3. **期待結果**: トップ画面に残額8,000円が表示される（SC-003）
4. さらに10,000円の支出を記録する
5. **期待結果**: 残額がマイナス2,000円として分かりやすく（例: 赤字表示で）表示される

### 6. バリデーション（FR-010, Edge Cases）

1. 支出記録の金額に `0` または `-100` を入力して保存を試みる
2. **期待結果**: エラーとして拒否され、記録が作成されない

## 完了の目安

上記1〜6がすべて成功すれば、spec.md の User Story 1・2・3（P1〜P3）に対応する主要フローが
エンドツーエンドで動作していると判断できる。
